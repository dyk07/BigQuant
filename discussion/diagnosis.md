## 已确认的数据质量问题

### 1. 盘口零报价 (CRITICAL — 已修复)
**现象**: ask_price1=0 占 1.9%, bid_price1=0 占 4.3%（各频率一致，bar1m 202002）
**性质（已实测确证）**: 0 不是"0 元"，而是**该侧无挂单**：
  - `ask_price1 == 0` → **涨停封板**（卖侧被买光）；其中 94.2% 该 bar 处于当日最高价
  - `bid_price1 == 0` → **跌停**或开盘初段买盘未形成；其中 99.8% 该 bar 处于当日最低价
  - 两者都满足 `*_volume1 == 0`（100%）
  - 涨停占 1.5–1.9%，跌停占 3.5–4.3%
**之前的错误**: 盘口价格=0 被当作有效的 0.00 元 → bid_price1_rel = 0/close-1 = -1.0
  → 对神经网络是极大的输入噪声（正常范围约 -0.02~+0.02，即噪声是信号的 50 倍）
**修复**: `restore_local_data()` 中**盘口价格** = 0.0 → NaN
  → 后续标准化时 NaN 被填为 0（即训练集均值），不再产生极端值
  → 注意**只处理价格**，盘口 volume/num_orders 保留原值（0 是真实的"无挂单"）
**为何不把"零报价"当特征**: 平台规则禁止手工因子（尤其买卖量不平衡类），
  涨跌停标记属于人工构造的因子，故统一按缺失处理，让模型自行从价格/量序列学习。

### 2. 标签定义 (CRITICAL — 方向已定案)
**会议纪要**: "WAP收益是用未来30分钟的成交量加权平均价除以未来30分钟窗口的**最终一笔成交价（end_price）**计算得出"
**平台真实口径(用户最终确认)**: `vwap_return = end_price / vwap - 1`
**本地训练口径(已统一)**: `label = end_price / future_vwap - 1`（与平台定义完全一致）
**方向处理**: 训练与推理方向统一，**不再**在推理侧 factor 取负号；此前的
  `vwap/end-1` + 推理取负 的临时方案已撤销。

### 3. 09:25 集合竞价 (IMPORTANT — 已修复)
**现象**: 09:25 bar 在**四个频率中都存在**，且约 40% 股票有真实成交
  （volume>0，bar30m 202002 = 7914/19980 行）
**之前处理**: 直接剔除 → 每个交易日只剩 8 个截面，且丢了开盘截面
**正确做法（用户确认）**: **保留 09:25**（开盘截面用集合竞价数据预测）；
  只剔除 bar1m 的 09:16–09:24 盘前价（volume=0、amount=0、close 与 09:25 相同，
  是集合竞价中的指示性价格）
**修复**: `filter_auction_and_tag_day()` 改为 `minute_of_day >= 9*60+25`；
  `config.valid_minutes()` 显式加入 09:25；`aligned_minutes()` = 09:25 ∪ 30 分网格
**结果**: 采样截面 = 09:25,10:00,10:30,11:00,11:30,13:30,14:00,14:30,15:00
  → 每个交易日 **8 个可用截面**（15:00 无未来窗口，标签 NaN 自动剔除），
  与平台"约 8 个日内截面"一致

### 4. 数据质量报告中的其他发现（复核结论）
- bar1m 202002: 8433 行 OHLC=-1（0.17%），集中在盘前 09:16–09:30 段 → 已剔除
- 无重复键、无 OHLC 大小关系异常、无盘口负报价
- 极端收益（|ret|>20%）仅 6 行（占比 0.0001%），其中 83.3% 前一根 volume=0
  （停牌复牌跳空）→ **量级可忽略，不需额外截断**
- `adjust_factor` 同一交易日内为常数（1001 只股票中仅 1 只在月内变化）
  → 窗口/标签都不跨交易日，无需复权
- 全月零成交的 stock-day 仅 13/19980

## 规则边界（来自 wechat + meeting_summary）
- 允许: 均值、标准差、log变换、标准化、中心化
- 禁止: 盘口买卖量不平衡、手工构造的技术指标/因子
- 允许: 神经网络直接输入原始分钟序列
